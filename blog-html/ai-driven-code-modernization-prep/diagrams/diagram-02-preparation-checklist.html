Preparation Checklist cho dự án legacy tại công ty outsourcing

Gợi ý áp dụng 6 bước vào dự án hiện đại hoá hệ thống legacy (PHP / Java / VB) cho khách hàng Nhật. Đánh dấu đủ trước khi cho agent chạy quy mô lớn.

Uplift (cùng stack, lên version)

Stack vẫn dùng được, chỉ runtime / thư viện đã hết hỗ trợ.

Ví dụ: PHP 5.x → PHP 8.x, Java 8 → 17/21, Spring Boot 2 → 3

Transform (đổi stack, giữ hành vi)

Hành vi đáng tin, nhưng ngôn ngữ / framework là vấn đề.

Ví dụ: VB6 / VB.NET WinForms → C# .NET, Struts → Spring

Reimagine (xây lại, đổi hành vi)

Cả code lẫn nghiệp vụ cần thay đổi; cần spec mới bằng văn bản.

Ví dụ: hệ thống nội bộ on-premise → web/SaaS với quy trình mới

1. Đích & Spec

Đã chọn loại Uplift / Transform / Reimagine cùng khách hàng
Có dependency map từ build log / import / runtime trace
Business rule trích từ code, có trích dẫn file, được người phía khách review
Lý do dự án ghi rõ (EOL, lỗ hổng, thiếu người bảo trì)

2. Certificate & Policy

Danh sách điều kiện tự động kiểm tra được (test, coverage, benchmark, scan)
So sánh output cũ/mới hoặc replay dữ liệu (đã che PII)
Phân tầng duyệt theo mức ảnh hưởng, đường critical vẫn review đầy đủ
Định dạng báo cáo review thống nhất với reviewer / khách

3. Môi trường & CI/CD

Remote host riêng, Claude Code truy cập được code và tài liệu
Môi trường chạy được hệ thống cũ (Docker) để so sánh
Chính sách code freeze + kế hoạch thông báo cho dev đang làm
CI chặn commit làm hỏng phần đã hiện đại hoá

4. Bảo mật & Hợp đồng

Khách hàng chấp thuận đưa source code vào model (theo NDA / hợp đồng)
Least-privilege: chỉ ghi vào nhánh modernization, không có credential production
Secret và dữ liệu cá nhân đã được che
Mỗi PR gắn transcript agent + bằng chứng certificate; kiểm tra license/CVE dependency mới
GATE
Chỉ mở rộng ra toàn bộ codebase khi: pilot trên 1 phân vùng nhỏ đã đi trọn quy trình (agent sửa → certificate pass → duyệt theo policy → merge) và đã đo token để ước tính chi phí.
