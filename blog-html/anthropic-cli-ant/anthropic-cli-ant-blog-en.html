1. Overview of Anthropic CLI (ant)

ant is the official CLI for the Claude Developer Platform, published by Anthropic under the MIT license. The anthropics/anthropic-cli repo started in Jan 2026; latest version at demo time: v1.10.0 (28 May 2026). It is a single Go binary with no Node/Python runtime dependency.

Design principle: every API resource is a subcommand. Instead of hand-crafted curl + JSON, you run ant messages create, ant models list, ant beta:agents create, etc. Request bodies accept typed flags, inline YAML, or piped files; responses support JSON/YAML formats and GJSON field extraction (--transform).

Per the Madni X article and launch coverage: ant is not only for Messages API calls — it is the fastest path to create, deploy, and operate Claude Managed Agents (agents, environments, sessions) from the terminal, ideal for scripts, CI/CD, and GitOps (YAML agent defs in Git). Anthropic also notes Claude Code can drive ant via the claude-api skill.

3. Core features (docs + README)

3.1. Messages API & Models

  • ant messages create — conversations with system prompt, tools, streaming, thinking.
  • ant models list — models available to your workspace.
  • ant messages:batches — async batch processing.

3.2. Beta: Managed Agents platform

  • beta:agents — create / update / list / archive agents.
  • beta:environments — cloud runtime for agents.
  • beta:sessions — sessions with events, threads, resources.
  • beta:files, beta:skills, beta:memory-stores, beta:vaults — supporting resources.

3.3. Auth & profiles

  • ant auth login — browser OAuth, local credential store.
  • ANTHROPIC_API_KEY — for scripts and CI.
  • ant profile — multiple profiles, org, OIDC federation.

3.4. Output & automation

  • --format: json, yaml, pretty, raw, jsonl, explore.
  • --transform / --transform-error — GJSON without extra tooling.
  • @file.ext — embed file contents (text or base64) in requests.
  • Shell completion: bash, zsh, fish, PowerShell.

4. Install on Windows 10

Demo environment: Windows 10, PowerShell. Per the CLI quickstart, official install tabs list Homebrew (macOS), curl (Linux/WSL), and Go only — no Windows tab. On native Windows, download the binary from GitHub Releases (ant_*_windows_amd64.zip). Or use WSL with the Linux instructions.

4.1. Download binary v1.10.0

Goal: Get a working ant.exe without installing Go.

$installDir = "C:\anthropic-cli-ant\tools"
New-Item -ItemType Directory -Force -Path $installDir
Invoke-WebRequest -Uri "https://github.com/anthropics/anthropic-cli/releases/download/v1.10.0/ant_1.10.0_windows_amd64.zip" -OutFile "$installDir\ant_1.10.0_windows_amd64.zip"
Expand-Archive -Path "$installDir\ant_1.10.0_windows_amd64.zip" -DestinationPath $installDir -Force

Equivalent script: demo-assets/01-install-windows.ps1

4.2. Verify install

cd C:\anthropic-cli-ant\tools
.\ant.exe --version
ant version 1.10.0

6. Managed Agents & GitOps (docs + Madni)

Step 8 above demonstrates beta:agents create. Full beta flow:

  1. Define agent in YAML (e.g. demo-assets/03-managed-agent-sample.yaml).
  2. ant beta:agents create < agent.yaml
  3. ant beta:environments create — provision cloud environment.
  4. ant beta:sessions create — open session with agent.
  5. ant beta:sessions:events create — send task, read trace/response.

Madni and Avinash Sangle highlight: commit YAML to Git, update agents in CI (ant beta:agents update --agent-id ... < agent.yaml) — GitOps for agent config without SDK wrappers. Session pricing in reference posts: ~$0.08/hour when active + standard token rates; idle time not billed for sessions.

7. Personal opinion: AI Quest workflow fit

Prior demos (Drive Projects, Workspace Studio, Gemini Sheets) rely mostly on Google Workspace UI or copy-paste prompts. ant adds an API/script layer underneath — useful when automation must run without a browser:

  • Offline batch content: After exporting meeting notes / PDF text from Drive demos, pipe into ant messages create --message @notes.txt for bulk summaries before re-uploading to Docs.
  • CI for blogs & docs: GitHub Actions runs ant messages create with demo-assets/04-gemini-blog-prompt.txt to draft sections; humans edit HTML — less blank-page friction for bilingual posts.
  • Managed Agent for “client pitch” pipeline: Deploy ops-review-assistant YAML once; each quarter only beta:sessions create + CSV upload — reuse logic instead of rewriting Drive Project prompts.
  • Claude Code + ant together: Claude Code edits HTML/MD in AI_QUEST_LTP; when API calls are needed (list models, token tests), let the agent run ant instead of embedding keys in throwaway Python scripts.
  • Does not replace Workspace CLI (gws): gws operates Drive/Sheets/Gmail; ant operates Claude API. Ideal pipeline: gws drive +upload → ant messages create summarize → write back via Workspace helpers.
Practices I would adopt: Always ant auth status + --transform-error in scripts; store agent YAML in demo-assets/; never hard-code API keys — use env or CI secrets.

9. Conclusion

ant is an official, compact, script-friendly way to work with the full Claude Developer Platform from the terminal. The Windows demo confirms: zip install is straightforward, --help is self-documenting, auth errors are structured JSON, and --transform fits shell pipelines without an SDK.

In the AI Quest demo stack (Workspace + Claude), ant fits best as automation & API glue — not a replacement for Gemini/Drive Projects UI for end users, but strong for operators, bloggers, and version-controlled agent deployment.
