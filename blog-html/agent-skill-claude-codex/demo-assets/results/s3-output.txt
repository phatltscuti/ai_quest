I wrote the requirements document in English, as you asked. It's saved to `docs/requirements/self-service-leave-cancellation.md`.

- **17 functional requirements, 10 non-functional requirements and 18 acceptance criteria.** Each acceptance criterion links to the requirement it checks. The non-functional requirements cover security, audit, privacy, performance and usability.
- **10 assumptions and 10 open questions.** The open questions are addressed to HR, PM or Dev.
- **Must-haves:** employees cancel their own pending or approved leave; once a leave has started, they can only cancel the remaining days. The manager is notified, cancelled days go back to the leave balance, and every cancellation is recorded in an audit log that can't be edited.

Things I found in `leave_service.py` that affect this feature:
- **New items the feature needs:** a `cancelled` status, an audit log table and a notification channel. None of these exist in the code yet, so the document marks them as *new*.
- **Manager for pending requests:** `leave_requests` has no manager field. Only `approver` exists, and it is filled in when a request is approved. So the system can't yet tell who to notify when someone cancels a pending request (Q-03).
- **Day-count bug:** `leave_days` is documented as counting both start and end dates, but it returns one day less. If it isn't fixed, the number of cancelled days will be wrong (A-07, Q-07).
- **Unsafe SQL query:** `find_requests_by_employee` builds its SQL from a string. NFR-02 requires the new feature to use parameterized queries.

The questions blocking the work are Q-01 (exact deadline), Q-02 (whether cancelling an approved leave needs manager approval), Q-03 and Q-04 (notification channel).
