## Code review: `leave_service.py`

| # | Severity | Location | Finding | Suggested fix |
|---|----------|----------|---------|---------------|
| 1 | Critical | leave_service.py:6 | `ADMIN_TOKEN` is hardcoded in source. Anyone with repo access can read it, and it stays in git history. | Treat the token as leaked and rotate it. Load it at runtime with `os.environ["ADMIN_TOKEN"]` or from a secrets manager, and fail fast if it is missing. |
| 2 | Critical | leave_service.py:15 | SQL injection. `name` goes straight into the query through an f-string, so `name = "x' OR '1'='1"` dumps every employee's requests. | Use parameter binding: `conn.execute("SELECT ... FROM leave_requests WHERE employee = ?", (name,))`. |
| 3 | Critical | leave_service.py:36-41 | No authorization check. `approver` is any string the caller passes, so an employee can approve their own request (`approver == row[0]`) and nothing checks that the approver has the approver role. | Pass in the authenticated user. Check that they hold the approver/HR role, and reject the call if `approver == employee`. |
| 4 | Major | leave_service.py:38-41 | No state-transition check. `status` is fetched but never used, so approved, rejected or cancelled requests can be approved again. Doing a SELECT and then a separate UPDATE also leaves a race window (TOCTOU). | Make the update atomic: `UPDATE leave_requests SET status='approved', approver=? WHERE id=? AND status='pending'`, then raise if `cur.rowcount == 0`. Use the earlier SELECT only to tell "not found" apart from "invalid state". |
| 5 | Major | leave_service.py:19-21 | Off-by-one error. The docstring says both dates are included, but `(end - start).days` leaves out the end date. A single-day leave (`start == end`) counts as 0 days. | `return (end - start).days + 1` |
| 6 | Major | leave_service.py:24,26 | `attachments=[]` is a mutable default argument. The same list is shared by every call, so each response also lists attachment filenames from earlier requests, including other employees' (wrong output and a data leak). | Use `attachments=None`, then `attachments = list(attachments or [])` before appending. |
| 7 | Minor | leave_service.py:24-25 | No input validation. `end < start` gives a negative `days` that is stored as-is. Empty `employee`/`reason` and non-`date` values are also accepted. | Validate at the top of `create_request`: check that the values are `date` instances, that `end >= start`, and that `employee`/`reason` are not blank. Raise `ValueError` on failure. |
| 8 | Minor | leave_service.py:47-50 | `except Exception: pass` swallows errors and returns `None`, so the caller gets `None` for the balance with no error raised. | Remove the try/except, or catch `TypeError` and re-raise as a meaningful `ValueError`. Never return `None` silently. |
| 9 | Minor | leave_service.py:14,27,37 | Connections are never closed (`get_conn()` with no close). Note that `with sqlite3.connect(...)` only commits or rolls back. It does not close the connection. | Use `with contextlib.closing(get_conn()) as conn, conn:` so the connection is closed and the transaction is handled in one place. |
| 10 | Minor | leave_service.py (whole file) | There are no tests for any of this logic: day counting, approval state and permissions, the SQL query, or the attachments behaviour. | Add pytest tests against an in-memory SQLite DB. Cover a single-day leave (=1), `end < start`, self-approval, approving twice, `name` containing a quote, and two consecutive `create_request` calls. |
| 11 | Nit | leave_service.py:15 | `SELECT *` ties callers to the column order and returns more data than they need. | List the columns explicitly. |
| 12 | Nit | leave_service.py:43 | `approve_request` always returns `True`. Failures already raise exceptions, so the return value tells the caller nothing. | Return `None`, or return the updated request. |
| 13 | Nit | leave_service.py:13,24,36,46 | Type hints and docstrings are missing on most public functions (only `leave_days` has them). | Add type hints and short docstrings. |

**Summary:** 3 Critical, 3 Major, 4 Minor, 3 Nit
