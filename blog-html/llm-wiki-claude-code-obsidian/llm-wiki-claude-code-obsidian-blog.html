1. Khái niệm LLM Wiki (tóm tắt khách quan)

Trong gist LLM Wiki, Andrej Karpathy mô tả một pattern xây dựng cơ sở tri thức cá nhân (hoặc nhóm) với LLM, khác với luồng quen thuộc kiểu RAG nơi tài liệu được upload và mô hình truy hồi đoạn văn rồi trả lời từng lần. Với LLM Wiki, LLM không chỉ “trả lời rồi quên”; nó biên soạn và duy trì một tập các file Markdown có cấu trúc, liên kết chéo, đặt ở giữa bạn và nguồn thô.

Khi có nguồn mới, agent đọc nguồn, trích thông tin, tích hợp vào wiki hiện có: cập nhật trang thực thể, revise tóm tắt chủ đề, ghi nhận mâu thuẫn với dữ liệu cũ nếu có. Như vậy tri thức được biên dịch một lần (quá trình ingest) và được giữ cập nhật qua các vòng bảo trì, thay vì buộc mô hình mỗi lần hỏi phải “vá” lại từ fragment.

Ba tầng (theo gist):
  • Raw sources — tài liệu gốc do bạn tuyển chọn; nguyên tắc là LLM đọc nhưng không tự ý sửa (trừ khi bạn giao rõ).
  • Wiki — thư mục Markdown do LLM/agent tạo và cập nhật; bạn đọc, agent viết.
  • Schema — tài liệu cấu hình (ví dụ CLAUDE.md cho Claude Code, hoặc AGENTS.md cho Codex) mô tả cấu trúc wiki, quy ước, quy trình ingest/query/lint.

Ba thao tác vòng đời được nhấn mạnh: Ingest (đưa nguồn và cập nhật nhiều trang wiki), Query (hỏi và tổng hợp có trích dẫn; câu trả lời giá trị có thể ghi ngược vào wiki), và Lint (rà soát mâu thuẫn, trang mồ côi, nội dung lạc hậu…). Hai file đặc biệt được đề xuất: index.md (mục lục theo chủ đề) và log.md (nhật ký theo thời gian, append-only).

2. Vai trò của Claude Code và Obsidian (giải thích khách quan)

Cả hai công cụ đều không thay thế nhau; chúng giải quyết hai lớp bài toán khác trong cùng một kiến trúc folder-based.

Thành phần Vai trò trong LLM Wiki
Claude Code (agent lập trình / CLI có quyền đọc-ghi file trong workspace) Là “người bảo trì wiki tự động”: đọc schema (CLAUDE.md), thực hiện ingest (tạo/sửa nhiều file trong wiki/), cập nhật index.md và log.md, trả lời câu hỏi có trích dẫn và có thể tạo thêm trang khi có giá trị tích lũy. Claude Code không bắt buộc phải là duy nhất có thể đóng vai này; gist gợi ý bất kỳ agent tương đương nào bạn tin dùng.
Obsidian (ứng dụng ghi chú Markdown, làm việc trực tiếp trên filesystem) Là “IDE cho người đọc”: render Markdown, điều hướng liên kết [[wiki links]], Graph view để nhìn cấu trúc liên kết, và các plugin (Dataview, Marp, clipper…) hỗ trợ làm giàu nguồn hoặc trình bày. Obsidian không định nghĩa quy trình ingest; nó chủ yếu phục vụ khám phá và đọc những gì agent đã ghi ra đĩa.

Cách Karpathy diễn đạt trong gist: có agent mở một bên, Obsidian mở một bên; agent sửa file theo hội thoại, người dùng theo dõi kết quả real-time trong Obsidian — meta-analogy: “Obsidian là IDE; LLM là lập trình viên; wiki là codebase.”

3. Thực hành: dựng môi trường LLM Wiki cơ bản

Phần dưới đây mô tả quy trình có thể lặp lại trên máy bạn. Song song, trong repo dự án này tôi đã khởi tạo sẵn một vault mẫu để bạn clone/mở trực tiếp làm điểm xuất phát (xem mục bằng chứng).

3.1. Chuẩn bị phần mềm

  1. Cài Obsidian từ trang chủ, phiên bản ổn định mới nhất phù hợp OS của bạn.
  2. Cài Claude Code (hoặc agent CLI bạn chọn), đảm bảo có quyền mở thư mục vault và đọc/ghi Markdown.
  3. (Tùy chọn) Cài Git để version-control toàn bộ vault như một repo.

3.2. Tạo cấu trúc thư mục (tối thiểu)

.
├── CLAUDE.md          ← schema / quy ước cho agent
├── raw/               ← nguồn thô (immutable theo convention)
└── wiki/
    ├── index.md       ← mục lục
    ├── log.md         ← nhật ký append-only
    ├── overview.md    ← có thể bắt đầu từ một trang tổng quan
    └── concepts/      ← các trang khái niệm / thực thể tuỳ domain
        └── ...

3.3. Viết CLAUDE.md (điều kiện tiên quyết)

Dán vào CLAUDE.md các quy tắc: ranh giới giữa raw/ và wiki/; định dạng tiêu đề log; luồng ingest (luôn cập nhật index + log); cách đặt internal link để Obsidian hiểu. Trong repo, file mẫu nằm tại đường dẫn trong mục 4 — bạn có thể chỉnh theo domain (nghiên cứu, sản phẩm nội bộ, sổ tay đọc sách…).

3.4. Mở vault trong Obsidian

  1. Obsidian → Open folder as vault → chọn thư mục gốc chứa CLAUDE.md (không chỉ riêng wiki/, trừ khi bạn cố ý tách vault).
  2. Bật preview, thử nhấp liên kết giữa wiki/overview.md và các trang con.
  3. Mở Graph view để quan sát mạng liên kết sau khi đã có vài note.

3.5. Vận hành Claude Code

  1. Mở terminal tại root vault (thư mục có CLAUDE.md).
  2. Khởi động Claude Code theo hướng dẫn của Anthropic và để agent tự đọc project rules từ CLAUDE.md (đừng thủ công copy toàn bộ gist mỗi phiên — schema đã thể chế hoá các quy tắc bạn muốn).
  3. Giao việc mẫu: “Đọc raw/<tên-file>.md, cập nhật wiki — tóm tắt, đổi/cập nhật ít nhất một trang concept, refresh wiki/index.md, append wiki/log.md.”
Lưu ý vận hành: LLM có thể bỏ sót hoặc bóp méo nếu không giám sát — với wiki dùng cho quyết định quan trọng, giữ vai trò con người phê duyệt cho các chỉnh sửa lớn và lưu phiên bản (Git commit) sau mỗi chuỗi ingest có ý nghĩa.
Gợi ý trong gist có thực dụng: Obsidian Web Clipper để đưa bài web vào Markdown nhanh; cấu hình thư mục attachment cố định nếu bạn muốn hình ảnh cục bộ cho downstream phân tích.

5. Hình minh hoạ và cách chụp ảnh demo

Các khung ảnh dưới đây trỏ tới file trong images/. Sau khi bạn chụp theo hướng dẫn chi tiết trong HUONG-DAN-DEMO-CHUP-ANH.md, hãy lưu đúng tên file để HTML tự nhúng.

Nếu chưa cài Obsidian hoặc cần ảnh minh họa nhanh, mở bộ giả lập trong mockup-screenshots/ (step-*.html): giao diện HTML giống Obsidian dark theme + Terminal, rộng cửa sổ khoảng 1280px rồi cắt màn hình để được PNG thay ảnh thật.

Các bước tuỳ chọn (terminal Claude Code, git status) và quy định đặt tên ảnh đầy đủ: đọc HUONG-DAN-DEMO-CHUP-ANH.md cùng thư mục với file HTML này.

Mẹo trình chiếu blog khi ảnh chưa đủ: các thẻ <img> dùng onerror để ẩn ảnh thiếu; sau khi bạn lưu file PNG vào images/, tải lại trang trên trình duyệt là thấy hình hiện đúng.

6. Ý kiến cá nhân: áp dụng vào công việc hàng ngày của tác giả bài viết và của “AI phụ tá”

6.1. Góc người (tác giả blog / làm việc tri thức và giao tiếp kỹ thuật)

Với các luồng như QA sản phẩm SaaS, tài liệu nội bộ và hộp thử nghiệm blog HTML, LLM Wiki giúp tách biệt rõ: hồ sơ gốc (transcript, báo cáo, gist, ticket) và bản đúc kết sóng sót (wiki). Việc bắt agent sau mỗi meeting hoặc mỗi issue lớn cập nhật đồng thời vài trang (Khách hàng X, Yêu cầu Z, Rủi ro) có thể giảm cảm giác “đã đọc nhưng không nhớ để ở đâu”. Chi phí thật không nằm ở gõ Markdown mà nằm ở kiểm duyệt định kỳ và phiên bản hoá Git — đầu tư này hợp lý khi wiki phục vụ quyết định chứ không chỉ lưu cảm tính đọc nhanh.

6.2. Góc AI phụ tá lập trình (ví dụ agent trong Cursor trên codebase)

Công cụ như Cursor (hoặc Claude Code trong terminal) đã quen làm việc với filesystem và chuẩn hoá trong CLAUDE.md. LLM Wiki chuyển trọng tâm từ “trả lời trong cửa sổ chat” sang “sản phẩm là các file có liên kết” — khớp với cách các team kỹ thuật tư duy về codebase. Tôi có thể áp dụng cụ thể: mỗi khi khảo sát một khu codebase lạ, ingest file ADR/nguyên tắc vào raw/, để agent cập nhật wiki/concepts và index.md, sau đó dùng Obsidian chỉ để tua nhanh không gian khái niệm trong khi tay vẫn code trong IDE — chat log không là nơi duy nhất đựng chi thức.
