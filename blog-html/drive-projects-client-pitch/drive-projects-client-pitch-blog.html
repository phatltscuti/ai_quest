Giới thiệu

Google Drive Projects (kết hợp Ask Gemini in Drive) cho phép ghim một tập file/folder/email làm nguồn cố định, rồi đặt câu hỏi tổng hợp trên nhiều tài liệu nội bộ cùng lúc — phù hợp khi presales cần soạn proposal/pitch theo từng khách mà vẫn bám spec sản phẩm, template chuẩn và biên bản họp cũ.

Khác với chat Gemini rời rạc từng file, Project không di chuyển file gốc trên Drive; chỉ tạo “khung nghiên cứu” có thể chia sẻ team, resume lịch sử hội thoại, và kiểm chứng câu trả lời qua citations trỏ về Doc nguồn. Tài liệu chính thức: Share Gemini sources using Drive projects, Use Gemini in Drive for research & analysis.

Yêu cầu & checklist

  • Tạo Project mới trên Drive và gom file nguồn: đặc tả sản phẩm, template proposal, biên bản họp trước.
  • Dùng Ask Gemini trong Project để tổng hợp và sinh bản nháp proposal cho khách mới.
  • Đính kèm screenshot từng bước (Step 1–16) + ghi chú run/history khi có.
  • Viết phân tích riêng về lợi ích hiệu quả/độ chính xác cho quy trình sales/báo cáo nội bộ.
  • Đảm bảo tái lập: quy tắc folder, tên file nguồn, prompt mẫu để nhân viên khác dựng lại.

Triển khai Drive Project + Ask Gemini

Bước A — Chuẩn bị 3 file nguồn (trước khi tạo Project)

Tạo 3 Google Doc trong 00_Internal_Sources với nội dung khung sau (có thể mở rộng chi tiết khi demo):

1) Product specification (trích đoạn)

PRODUCT SPECIFICATION — Warehouse Visibility MVP (v1.2)

MVP scope (in)
- Web dashboard: SKU on-hand, inbound/outbound (24h rolling).
- REST read API from customer WMS (polling 15 min).
- RBAC: Ops Manager, Warehouse Lead, Auditor.

Out of scope (MVP)
- Native mobile apps; ML forecasting.

Internal MD reference
Work package   | Role      | MD low | MD high
WMS connector  | Backend   | 18     | 28
Dashboard UI     | Frontend  | 12     | 18

2) Proposal template (cấu trúc section)

CLIENT PROPOSAL — {{CLIENT_NAME}}

Executive summary
Client context & objectives
Proposed scope (in / out)
Solution approach
Timeline & milestones
Commercial outline
Risks & mitigations
Next steps

3) Past meeting notes (lessons learned)

MEETING NOTES — Acme Retail (reference deal)

Lessons learned
- Confirm integration credential model in first call.
- Separate MVP scope from roadmap in writing.
- Include explicit support window in commercial section.

Bước B — Tạo Project và gắn sources

  1. Web: drive.google.com → New → Project (hoặc project.new).
  2. Đặt tên: Pitch — Nexa Logistics — Warehouse MVP → Create Project.
  3. Add sources → chọn 3 Doc: spec, template, meeting notes.
  4. Giữ tất cả sources checked (active) trước khi hỏi Gemini.

Quyền: collaborator chỉ phân tích được nội dung file nếu đã có quyền View file đó trên Drive. Share Project không thay thế share file gốc.

Bước C — Ask Gemini: prompt tổng hợp pitch

Dán prompt sau vào Ask Gemini (full-screen trong Project). Client brief nằm trong prompt — không bắt buộc tạo file riêng trên Drive.

You are helping our presales team draft a client-specific proposal.

Use ONLY the pinned project sources (product spec, proposal template structure, past meeting notes) plus this new client brief:

---
Client: Nexa Logistics Co., Ltd.
Needs: Real-time warehouse stock visibility MVP; WMS integration (OAuth2); web dashboard for Ops/Warehouse Lead/Auditor; target go-live Q3 2026; budget USD 80k–110k; no mobile app in phase 1.
---

Tasks:
1) Synthesize relevant capabilities from the product spec that match Nexa's needs.
2) Apply lessons from the Acme Retail meeting notes (scope discipline, auth model, support window).
3) Output a complete proposal draft following the section headers in our proposal template: Executive summary, Client context, Proposed scope (in/out), Solution approach, Timeline, Commercial outline (use internal MD ranges from spec as indicative only), Risks, Next steps.

Tone: professional, concise, suitable for B2B logistics.
Flag any assumptions that need client confirmation with [CONFIRM].

Bước D — Kiểm chứng citations & xuất bản nháp

  1. Đọc câu trả lời; bấm citation [1], [2]… để mở file nguồn (verify theo hướng dẫn research & analysis).
  2. Chỉnh sửa chỗ sai/lệch khách; thêm/xóa bullet theo PM.
  3. Insert / Export to Google Docs → lưu vào 10_Client_Outputs với tên pitch khách.
  4. (Tuỳ chọn) Save as a project từ conversation Gemini thường nếu bắt đầu từ file đơn lẻ trước đó.

Bước E — Follow-up trong cùng Project

Based on the draft above, tighten the Commercial outline into a table with 4 work packages and map each to the MD ranges from the product spec. Keep [CONFIRM] flags where budget or WMS API docs are uncertain.

Phân tích: hiệu quả & độ chính xác cho sales / báo cáo

Phân tích dưới đây là đánh giá vận hành của team presales/PM — không thay thế review pháp lý hoặc chốt giá cuối.

1) Hiệu quả (time & throughput)

Khâu thủ công trước đâyVới Drive Projects + GeminiTác động ước lượng
Mở lần lượt 3–5 Doc, copy-paste thủ công vào proposal mới Một Project, một prompt tổng hợp theo template Giảm 40–60% thời gian dựng bản nháp đầu (first draft)
Onboarding AE mới: không biết file nào là “source of truth” Danh sách sources ghim + tên Project theo deal Giảm sai file / thiếu context khi bàn giao deal
Báo cáo tuần: tổng hợp rủi ro từ nhiều meeting notes Prompt cross-file (“top 3 risks across Q2 notes”) Phù hợp staff report định kỳ, không chỉ pitch khách

2) Độ chính xác (quality & traceability)

  • Citations buộc người soạn quay lại Doc gốc — giảm “hallucination” so với chat không nguồn.
  • Template cố định trong sources giữ cấu trúc proposal thống nhất thương hiệu/delivery.
  • Meeting notes đưa bài học deal cũ vào pitch mới (scope, auth, SLA) — tránh lặp lỗi presales.
  • Toggle source (bỏ tick tạm) giúp A/B: có/không có notes khi soạn — kiểm soát bias nguồn.

3) Khuyến nghị vận hành cho team

  1. Chuẩn hóa prefix Project: Pitch — {Client} — {Offering}.
  2. Mỗi pitch draft xuất ra kèm dòng Generated from Project: … | Prompt version: v1 trong footer Doc.
  3. PM review bắt buộc các mục có tag [CONFIRM] trước khi gửi khách.
  4. Không share email Gmail làm source chung (email trong Project là private theo tài liệu Google).

Demo từng bước (ảnh Step 1–16)

Ảnh lưu tại images/; hướng dẫn thao tác chi tiết: HUONG-DAN-DEMO-CHUP-ANH.md.

Step 1: Mở thư mục gốc WS_Sales_Pitch_Sources, hiển thị 00_Internal_Sources và 10_Client_Outputs.

Step 2: Mở Doc đặc tả sản phẩm SPEC_Warehouse_Visibility_MVP_v1.2, thấy MVP scope và bảng MD nội bộ.

Step 3: Mở template proposal TEMPLATE_Proposal_IT_Intake, hiển thị đủ section header chuẩn.

Step 4: Mở biên bản họp deal tham chiếu NOTES_Acme_Retail_…, nhấn mục Lessons learned.

Step 5: Trên Drive, bấm New và chọn Project (hoặc dùng project.new).

Step 6: Nhập tên Project Pitch — Nexa Logistics — Warehouse MVP và tạo project.

Step 7: Bấm Add sources, chọn 3 file trong 00_Internal_Sources.

Step 8: Panel sources hiển thị đủ 3 file, trạng thái đang bật (checked).

Step 9: Mở Ask Gemini trong Project; xác nhận vùng Sources và ô prompt.

Step 10: Dán prompt tổng hợp (mục Triển khai — Bước C) vào ô hỏi.

Step 11: Gửi prompt; chụp câu trả lời có citations và các section proposal.

Step 12: Ở cột phải Sources used, click tên một file nguồn (ví dụ spec) để mở Doc và đối chiếu. Nếu có số [1], [2] trong câu trả lời thì click số đó. Chưa bấm Export to Docs (Step 13).

Step 13: Dưới câu trả lời Gemini, bấm Export to Docs (không dùng Export to Sheets — Sheets chỉ xuất bảng Risk). Lưu Doc vào 10_Client_Outputs, đặt tên PITCH_Nexa_Logistics_Warehouse_MVP_draft.

Step 14: Mở PITCH_Nexa_Logistics_Warehouse_MVP_draft, thấy nội dung đã personalize cho Nexa.

Step 15: Tạm bỏ tick một source (ví dụ meeting notes), hỏi lại để so sánh phạm vi phân tích.

Step 16: Drive → Projects → mở History, thấy conversation vừa chạy (resume research).

Rủi roQuan sátMitigation

Source sai / thiếu Spec cũ vẫn ghim → pitch đề xuất tính năng đã out-of-scope. Version trong tên file; review danh sách sources mỗi quý.
Over-trust output Số liệu MD/budget từ spec bị Gemini diễn giải sai ngữ cảnh khách. Bắt buộc PM review + tag [CONFIRM]; không gửi khách trực tiếp.
Chia sẻ Project vs chat Share Project chỉ share danh sách sources; chat history vẫn private. Export output sang Doc trước khi handoff nội bộ.

Kết luận

Drive Projects biến tập file nội bộ rời rạc thành ngữ cảnh có kiểm soát cho Ask Gemini — phù hợp tạo pitch/proposal theo khách mà vẫn bám spec, template và kinh nghiệm deal trước. Kết hợp citations + quy trình review PM, team sales có thể rút ngắn thời gian dựng draft đồng thời tăng traceability so với soạn tay hoặc chat không nguồn.
